# Movere AI

A digital wellbeing and focus app built with Flutter. Movere helps users
track focus sessions, build healthier screen habits, follow their progress
through a personal "Reality Score", and get lightweight AI-backed
suggestions based on their own real activity.

> Internship project — developed with Agile Scrum (weekly sprints,
> progress reports every 2 days). Currently in the Finalization phase
> (10–17 August), preparing MVP v1.0.

## Feature Set (MVP v1.0)

- **Authentication** — Firebase Auth (email/password), with auto-login
  on relaunch and Sign Out
- **Dashboard** — floating navigation (Home / AI / Academy) with a
  hamburger drawer for Progress, Usage Insights and appearance
- **Focus Mode** — four session lengths, live timer, interruption
  tracking, session history
- **Reality Score** — a real, computed score (not a placeholder) blending
  today's focus goal, recent session completion rate, and reading
  progress, with a message that changes with the score
- **AI Recommendation** — a dedicated AI tab: four always-on insights
  (Focus / Reading / Listening / Explore) plus a Q&A box. Real replies
  come from a Firebase Cloud Function calling OpenAI (the API key never
  ships in the app — see *Tech Decisions*); a local rule-based responder
  is the fallback if that backend is unreachable. The AI auto-detects and
  replies in whichever language a question is asked in
- **Academy** — lesson library with categories, reading-progress
  tracking, and bookmarks
- **Podcast** — real audio playback per lesson, with a persisted
  "listened" indicator
- **Progress Analytics** — weekly focus chart, session history
- **Settings** — profile, appearance (Light/Dark/System), language
- **Local persistence** — SQLite (`sqflite`) for everything that should
  survive a restart: profile, focus sessions, reading progress,
  bookmarks, listened episodes
- **Localization** — full EN/TR support, live-switchable from Settings

## Architecture

Feature-first structure: `lib/features/<feature>/{presentation,
application, domain}`. Shared UI/theme/utilities live under `lib/core`.
Localization strings live under `lib/l10n` (`.arb` source files;
`app_localizations*.dart` is generated by `flutter gen-l10n`, run
automatically by `flutter pub get`).

## Design System — "Move Beyond"

Dark-first identity with neon green accents.

| Role | Hex |
|---|---|
| Primary (neon green) | `#4ADE80` |
| Secondary (teal) | `#34D399` |
| Background (dark, default) | `#0A0E0C` |
| Surface (dark) | `#131A16` |
| Background (light) | `#F6FAF7` |

Typography: **Poppins** (headings) + **Inter** (body) via Google Fonts.

Components: `MovereButton`, `MovereCard`, `MovereTextField`,
`MovereAppBar`, `MovereBottomNav`, `MovereLoading` / `MovereSkeleton`,
`MovereProgressRing` (CustomPaint, gradient). All components take their
styling from the central theme — no hard-coded colors inside widgets.

## Tech Decisions

- **State management:** Riverpod (compile-time safety, low boilerplate)
- **Local database:** SQLite (`sqflite`)
- **Backend (auth):** Firebase Authentication
- **Backend (AI):** Firebase Cloud Functions (`functions/`) proxy calls
  to OpenAI — this keeps the API key server-side only, in Firebase
  Secret Manager, never in the client app or the repository
- **Charts:** fl_chart
- **Localization:** flutter_localizations + intl (EN/TR)
- **Git:** commits are SSH-signed (shown as "Verified" on GitHub)

## Getting Started

```bash
git clone https://github.com/dicleozgendev/movere-ai.git
cd movere_ai
flutter pub get
flutter run
```

Two things are required but not included in this public repository
(see *Audio Assets* and below for why):

- `ios/Runner/GoogleService-Info.plist` — your own Firebase project's
  config file (Firebase Authentication won't initialize without it)
- An `OPENAI_API_KEY` Firebase secret, only needed if you want the AI
  tab's real-AI replies — without it, the AI tab still works using its
  local rule-based fallback

Lint rules live in `analysis_options.yaml` — `flutter analyze` should
stay clean.

## Audio Assets

The Academy podcast episodes reference recordings in `assets/audio/`,
which are intentionally **not included in this public repository** — the
voice used belongs to a third party under a signed agreement limiting its
use to this app. Running the app without these files simply means the
podcast player has nothing to load; everything else works as normal.
Contributors with access to the recordings can drop them into
`assets/audio/` locally (see `pubspec.yaml` for the expected filenames).
